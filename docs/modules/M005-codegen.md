# M005 codegen

## 功能详细描述与预期

读取程序集元数据与配置，生成 C# 绑定代码，并作为命令行工具输出。生成物包含类型包装、delegate 调用器、interface 实现与注册代码；编译后替换反射兜底路径。

**场景**

- 开发者写好 C# 类型与 `lua-loom.json`，执行 `lua-loom-gen generate` 产出 `.g.cs`。
- CI 执行 `lua-loom-gen check`，确认仓库里的生成物与重新生成的结果一致。
- 运行期启动时，消费方调用 `LuaBindings.Register(env)`，把生成的类型绑定与 invoker 注册进当前环境。
- `csharpCallLua` 可以直接写闭合泛型 delegate（`System.Action<int>`、`System.Func<int, string>`、自定义 `Mapper<int, string>`），生成对应 invoker。

**边界**

- 不执行 IL 改写，不读 PDB，不做运行时类型发现。
- 不定义类型映射规则（M002 负责），只按规则产出调用代码。
- 不参与运行时决策：生成失败不降级，直接报错。

**预期（可观察）**

| 编号 | 预期 | 观察方式 |
| :-- | :-- | :-- |
| E1 | 对同一输入重复执行 `generate`，产物字节完全一致 | 两次生成后比较 SHA-256 |
| E2 | 产物含 `<auto-generated/>` 头与固定命名空间，不含时间戳与绝对路径 | 文本检查 |
| E3 | `check` 发现产物与重新生成结果不一致时退出码为 `1`，并列出差异文件 | CI 脚本断言 |
| E4 | 配置中类型不存在时输出诊断 `LL0001` 并退出码 `2` | 构造错误配置 |
| E5 | 生成的注册代码只注册配置中列出的类型 | 运行期检查缓存条目数 |
| E6 | 生成产物通过 Roslyn 语法校验，并在测试里用 `CSharpCompilation` 编译通过 | 生成非法类型名触发；编译测试断言 Emit 成功 |
| E7 | 闭合泛型 delegate 可解析并生成，类型名与 `typeof` 使用完整泛型形式 | 配置 `Action<int>`、`Func<int,string>`、自定义 `Mapper<int,string>` 后编译通过 |
| E8 | 开放泛型（``Action`1``、`Action<>`）输出 `LL0003` | 构造两类错误配置 |
| E9 | 泛型产物的文件名稳定、只含字母数字与下划线 | 文件名不出现 `<`、`,`、`[`、程序集版本 |

**非目标**

- 增量编译级的细粒度缓存（P0 只做文件级比对）。
- 为泛型开放类型生成代码（只支持闭合泛型）。
- 多语言输出（只产出 C#）。

## 使用与交互设计

**调用方**：开发者、CI、示例项目。

**配置文件 `lua-loom.json`**

```json
{
  "assembly": "artifacts/bin/LuaLoom.Sample/release/LuaLoom.Sample.dll",
  "output": "samples/LuaLoom.Sample/Generated",
  "namespace": "LuaLoom.Sample.Generated",
  "luaCallCSharp": ["LuaLoom.Sample.Player", "LuaLoom.Sample.Config", "LuaLoom.Sample.PlayerExtensions"],
  "csharpCallLua": ["LuaLoom.Sample.ILuaUpdate", "System.Action<int>", "System.Func<int, string>"]
}
```

**命令**

```powershell
lua-loom-gen generate --config lua-loom.json
lua-loom-gen check    --config lua-loom.json
```

| 场景 | 退出码 | 输出 |
| :-- | :-- | :-- |
| 生成成功 | `0` | 写入的文件数 |
| 配置或类型错误 | `2` | 诊断码、文件、行号 |
| `check` 发现差异 | `1` | 差异文件清单 |
| 参数缺失 | `64` | 用法说明 |

**异常表**（作为库调用时）

| 异常 | 触发条件 | 调用方处理 |
| :-- | :-- | :-- |
| `CodeGenException` | 配置非法、类型缺失、生成结果无法编译 | 终止构建 |
| `FileNotFoundException` | `assembly` 路径不存在 | 终止构建，提示先编译 |
| `IOException` | 输出目录不可写 | 终止构建 |

**界面**：命令行即交互面；无 GUI。

## 具体实现细节

**数据结构**

`GeneratorConfig`：

| 字段 | 类型 | 含义 |
| :-- | :-- | :-- |
| `Assembly` | `string` | 目标程序集路径 |
| `Output` | `string` | 输出目录 |
| `Namespace` | `string` | 生成代码命名空间，默认 `LuaLoom.Generated` |
| `LuaCallCSharp` | `string[]` | 需要生成包装的类型全名 |
| `CSharpCallLua` | `string[]` | 需要生成调用器的 delegate 与 interface |

JSON 键统一 camelCase，反序列化到上表的 PascalCase 属性。struct 的零 GC 传递由运行时按类型自动判定，不需要配置。

**产物结构**

| 文件 | 内容 |
| :-- | :-- |
| `<Type>.g.cs` | 类型绑定：`LuaTypeBinding` 的构造、`StaticIndex`/`StaticNewIndex`、`InstanceIndex`/`InstanceNewIndex` 五个 thunk |
| `<Delegate>.g.cs` | 实现 `ILuaDelegateInvoker.Create(LuaFunction)`，返回按参数类型直接调 `LuaBinding` 原语的 delegate |
| `<Interface>.g.cs` | 实现接口，成员转成表字段与方法调用 |
| `LuaBindings.g.cs` | 显式注册入口 `LuaBindings.Register(LuaEnv env)`，把类型绑定与 invoker 注册进环境 |

**算法**

1. 读取配置，校验字段完整性；相对路径以配置文件所在目录为基准解析。
2. `MetadataLoadContext` 加载目标程序集及其依赖，解析每个类型全名；缺失则记 `LL0001`。`csharpCallLua` 支持 `Name<Arg1, Arg2>`：先查目标程序集、核心程序集与已加载程序集，再递归解析泛型参数并 `MakeGenericType`；基本类型别名映射到 CLR 类型。
3. 遍历类型成员：跳过非公共成员、`obsolete` 成员，以及生成器不支持的类型（普通数组、泛型类型等）；被跳过的成员由 M004 的反射回落接管，不记错误。基类成员只有在直接基类也列入 `luaCallCSharp` 时才纳入。
4. 对 delegate/interface 生成 invoker 或实现类；配置中的静态扩展类额外生成 `RegisterExtensionType` 注册；类型绑定包含非字符串键索引器 thunk。同参数个数的方法重载按 Lua 类型条件分派（字符串、布尔、整数、数值、userdata 等），无法覆盖的组合仍回退反射；单方法默认值参数按实参个数生成多个分支并补齐缺省值；单方法 `ref`/`out`/`params` 生成参数装配与多返回值；一维数组通过 `LuaBinding.ReadArray<T>` / `PushArray<T>` 编解码。闭合泛型 delegate 的 `TypeRef` 递归输出 `global::Namespace.Type<...>`，文件名用 `TypeRef` 做字符白名单替换，避免写入尖括号、逗号与程序集限定名。
5. 用 `CSharpSyntaxTree.ParseText` 做语法校验；真正的编译校验放在测试里，用 `CSharpCompilation` 对产物做一次 Emit。
6. 通过后按文件名 `Ordinal` 排序写文件，UTF-8 无 BOM，换行 `\n`。
7. `check` 模式重新生成到内存，与磁盘文件逐字节比较，差异输出文件清单。

**复杂度**：O(类型数 × 成员数)；生成 100 个类型的耗时上限在模块验收中定为 5 秒以内（本机）。

**接口契约与错误传播**

- 生成代码只调用 `LuaBinding` 的强类型原语与 `LuaEnv` 的公共成员，不接触 `LuaApi`，也不自行管理栈顶；栈守卫由核心的 `LuaCSFunction` thunk 统一负责。
- 注册是显式的：消费方创建 `LuaEnv` 后调用 `LuaBindings.Register(env)`，把类型、delegate、interface 三类绑定注册进环境，不使用 `ModuleInitializer`，避免全局静态注册表。
- 产物是普通 `.cs` 文件，放回项目目录即被 SDK 默认通配包含，不需要手写 `<Compile Include>`。
- 生成器依赖 `Microsoft.CodeAnalysis.CSharp`，只作为 CLI 的构建期依赖，不随运行时库发布。
- 诊断码固定：`LL0001` 类型不存在、`LL0002` 成员类型不支持、`LL0003` 开放或不受支持的泛型、`LL0004` 配置重复、`LL0006` 产物语法错误。
- 生成失败时不写任何文件，避免留下半成品。

**当前支持范围**

| 支持 | 不支持 |
| :-- | :-- |
| public 构造函数（按参数个数分派） | 泛型类型、泛型方法、嵌套类型 |
| 实例/静态字段与属性（可读可写） | 事件、操作符的生成（运行期仍走反射） |
| 实例索引器（非字符串键） | 字符串键索引器、静态索引器 |
| 已配置基类的继承成员 | 未配置基类的成员 |
| 实例/静态方法（含同参数个数重载，按 Lua 类型分派） | 扩展方法（运行期回落反射） |
| 单方法 `ref`/`out`/`params` | 与其他重载混合的复杂参数组 |
| 单方法默认值参数（按缺省值补齐） | 默认值与同参数个数重载混合的组 |
| 非泛型 delegate 与闭合泛型 delegate（如 `Action<int>`） | 开放泛型 delegate |
| interface 的方法与属性（含闭合泛型接口） | 接口默认实现、显式接口实现 |
| 扩展方法类（列入 `luaCallCSharp`，生成注册） | 未配置的扩展方法不扫描、不可见 |
| 一维数组参数/返回值（基本类型、字符串、枚举、`object`） | 多维数组、类元素数组 |

同一参数个数的多个重载取声明顺序第一个；多类型重载的精确解析留给运行时反射路径。生成器跳过的成员不会丢失，由 [M004](M004-interop-bridge.md) 的回落路径接管。

**资源**：无外部资源；模板以 `StringBuilder` 拼接，不引入模板引擎。

## 测试方案

| 输入 | 操作 | 预期 |
| :-- | :-- | :-- |
| 含 3 个类型的示例程序集 | `generate` | 产出 4 个文件，编译通过 |
| 同一输入执行两次 | 比较哈希 | 完全一致 |
| 修改磁盘上的生成文件 | `check` | 退出码 `1`，列出该文件 |
| 配置里写不存在的类型 | `generate` | 诊断 `LL0001`，退出码 `2`，无文件写入 |
| 配置含开放泛型 `List<>` | `generate` | 诊断 `LL0003`，退出码 `2` |
| `csharpCallLua` 含 `System.Action<int>` | `generate` + 编译 | 产物含 `new global::System.Action<int>`，Emit 成功 |
| `csharpCallLua` 含 `System.Func<int, string>` | `generate` + 编译 | 多参数泛型解析正确，Emit 成功 |
| `csharpCallLua` 含自定义 `Mapper<int, string>` | `generate` + 编译 | 目标程序集开放泛型闭合正确 |
| 配置 ``System.Action`1`` 或 `System.Action<>` | `generate` | 诊断 `LL0003` |
| 检查泛型产物文件名 | 文本检查 | 仅字母数字与下划线 |
| 同一方法存在两个同参数个数重载 | `generate` | 整个方法组不生成，运行时走反射评分 |
| 类型含 `[Obsolete]` 方法/字段 | `generate` | 产物不含该成员 |
| 类型含同参数个数重载 | `generate` | 产物包含类型条件分派，编译通过 |
| 单方法带默认值参数 | `generate` | 产物按实参个数生成分支，编译通过 |
| 单方法 `out`/`ref`/`params` | `generate` | 产物生成 `out`/`ref` 调用与数组装配，编译通过 |
| 方法参数/返回值为 `int[]` | `generate` | 产物使用 `ReadArray<int>` / `PushArray<int>`，编译通过 |
| 派生类 + 已配置基类 | `generate` | 派生类绑定包含基类字段/属性/方法 |
| 派生类单独配置 | `generate` | 不生成未配置基类成员 |
| 类型含 `this[int]` | `generate` | 绑定含 `InstanceIndexer`/`InstanceIndexerSet` |
| 同一类型在 `luaCallCSharp` 出现两次 | `generate` | 诊断 `LL0004`，退出码 `2` |
| 输出目录只读 | `generate` | 抛 `IOException`，已有文件不被破坏 |
| 生成物被手改 | `check` | 退出码 `1` |

异常覆盖四类：空与边界（空的 `luaCallCSharp`、零成员类型）、非法输入（错误全名、开放泛型、重复配置）、依赖失败（程序集缺失、依赖解析失败、目录不可写）、重复与并发（重复执行、两个进程同时写同一输出目录时用文件锁串行）。
